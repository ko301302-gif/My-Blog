# 오늘 배운 것

클로드 코드와 함께 이 블로그를 직접 만들어보면서, HTML·CSS·JavaScript가 각각 어떤 역할을 맡는지 몸으로 느낄 수 있었습니다. 프레임워크 없이 세 가지만으로 사이트 하나를 완성해보니 역할 구분이 훨씬 선명하게 보였습니다.

## HTML — 뼈대를 세운다

`index.html`은 페이지를 두 번 만들지 않습니다. 글 목록을 보여주는 영역(`#post-list`)과 글 상세를 보여주는 영역(`#post-detail`)을 처음부터 함께 넣어두고, 상황에 따라 하나만 보이도록 JavaScript가 전환하는 구조입니다. HTML은 "어떤 요소들이 존재하는가"를 정의할 뿐, 언제 보이고 숨겨질지는 관여하지 않습니다.

```html
<section id="post-list" class="post-list"></section>
<article id="post-detail" class="post-detail" hidden></article>
```

## CSS — 보이는 방식을 결정한다

- **다크모드**는 색상을 CSS 변수(`--color-bg`, `--color-text` 등)로 뽑아두고, `prefers-color-scheme`과 `data-theme` 속성에 따라 변수 값만 바꿔서 구현했습니다. 색을 하나하나 바꾸는 게 아니라 변수 집합을 통째로 교체하는 방식이라 유지보수가 쉬웠습니다.
- **반응형**은 본문 폭을 제한(`--content-width: 680px`)하고 미디어 쿼리로 좁은 화면에서 여백과 글자 크기를 조정하는 정도로 충분했습니다.
- 직접 겪은 함정도 있었습니다. `hidden` 속성으로 요소를 숨기려 했는데, `.post-list { display: flex }` 같은 규칙이 있으면 브라우저 기본 스타일(`[hidden] { display: none }`)을 덮어써 버려서 숨김 처리가 안 되는 문제가 있었습니다. `[hidden] { display: none !important; }`를 명시적으로 추가하고 나서야 해결됐습니다. CSS의 우선순위는 명시성뿐 아니라 "누가 정의했는가"(브라우저 기본 vs 내가 쓴 스타일)도 영향을 준다는 걸 실감했습니다.

## JavaScript — 데이터를 가져오고 상태를 관리한다

- `fetch`로 `posts.json` 매니페스트와 각 글의 `.md` 파일을 읽어옵니다.
- `marked.parse()`로 마크다운 텍스트를 HTML로 변환해 화면에 꽂아 넣습니다.
- URL의 해시(`#/`, `#/post/slug`)를 읽어 목록 화면과 상세 화면 중 무엇을 보여줄지 결정하는 아주 단순한 라우터를 직접 만들었습니다.
- 다크모드 선택은 `localStorage`에 저장해서, 사용자가 고른 테마가 새로고침 후에도 유지되도록 했습니다.

## 정리

한 줄로 요약하면, **HTML은 무엇이 있는지, CSS는 어떻게 보이는지, JavaScript는 언제·왜 바뀌는지**를 담당했습니다. 프레임워크 없이 만들어보니 이 셋의 경계가 라이브러리 뒤에 가려지지 않고 그대로 드러나서, 오히려 기본기를 복습하기에 좋은 경험이었습니다.
