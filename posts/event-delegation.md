# 이벤트 위임(Event Delegation)으로 리스너 똑똑하게 관리하기

리스트 안에 버튼이 100개 있다면, 버튼마다 클릭 이벤트 리스너를 하나씩 다는 게 맞을까요? 개수가 늘어날수록 등록해야 할 리스너도 늘어나고, 나중에 버튼이 동적으로 추가되면 그 버튼에는 리스너가 붙어있지 않아 동작하지 않는 문제도 생깁니다. 이럴 때 쓰는 기법이 이벤트 위임입니다.

## 이벤트 버블링이 핵심

이벤트 위임은 이벤트가 발생한 요소에서 시작해 부모 요소로 타고 올라가는 '버블링' 특성을 이용합니다. 자식 요소 하나하나에 리스너를 달지 않고, 공통 부모에 리스너를 하나만 달아도 자식에서 발생한 이벤트를 감지할 수 있습니다.

```js
document.querySelector('.list').addEventListener('click', (e) => {
  if (e.target.matches('button')) {
    console.log('클릭된 버튼:', e.target.textContent);
  }
});
```

`e.target`은 실제로 클릭된 요소를 가리키므로, 어떤 자식이 눌렸는지 정확히 구분할 수 있습니다.

## 어떤 점이 좋을까

리스너 개수가 줄어 메모리 사용이 가벼워지고, 나중에 자식 요소가 동적으로 추가되거나 제거되어도 부모의 리스너가 그대로 작동해 별도 처리가 필요 없습니다. 목록, 테이블, 메뉴처럼 항목이 자주 바뀌는 UI에서 특히 유용합니다.

## 주의할 점

모든 상황에 적합한 건 아닙니다. 버블링되지 않는 이벤트(예: `focus`, `blur`)는 위임이 그대로 통하지 않으니 `focusin`, `focusout`처럼 버블링되는 대체 이벤트를 사용해야 합니다. 또한 `e.target`이 정확히 원하는 요소인지 확인하는 조건문을 꼼꼼히 작성하지 않으면, 의도하지 않은 자식 요소의 클릭까지 처리될 수 있습니다.
