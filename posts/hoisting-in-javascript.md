# 호이스팅(Hoisting), 변수 선언이 끌어올려지는 이유

아직 선언하지 않은 변수를 코드 위쪽에서 사용했는데도 에러 없이 `undefined`가 출력되는 걸 본 적이 있나요? 자바스크립트에는 변수와 함수 선언을 코드 실행 전에 미리 끌어올리는 '호이스팅'이라는 동작 방식이 있기 때문입니다. 정확히 어떻게 동작하는지 알아두면 예상치 못한 버그를 줄일 수 있습니다.

## var는 선언만 끌어올려진다

```js
console.log(name); // undefined
var name = '철수';
```

`var`로 선언한 변수는 선언부만 끌어올려지고, 값을 대입하는 부분은 원래 위치에 그대로 남습니다. 그래서 선언 전에 접근해도 에러가 나지 않고 `undefined`가 출력됩니다. 코드를 읽을 때 헷갈리기 쉬운 부분이라 실수의 원인이 되기도 합니다.

## let, const는 '일시적 사각지대'에 놓인다

```js
console.log(age); // ReferenceError
let age = 20;
```

`let`과 `const`도 사실 호이스팅되긴 하지만, 선언 이전 구간에서는 접근 자체가 막혀 있습니다. 이 구간을 '일시적 사각지대(Temporal Dead Zone)'라고 부릅니다. 덕분에 초기화 전 사용이라는 실수를 에러로 바로 확인할 수 있어 `var`보다 안전합니다.

## 함수 선언식은 통째로 끌어올려진다

```js
greet(); // 정상 동작
function greet() {
  console.log('안녕하세요');
}
```

`function` 키워드로 만든 함수 선언식은 선언과 내용 전체가 끌어올려지므로 선언 전에 호출해도 문제없이 실행됩니다. 반면 `const greet = () => {}` 같은 함수 표현식은 변수 호이스팅 규칙을 그대로 따르므로 선언 전에 호출하면 에러가 납니다.

## 정리

호이스팅을 완벽히 이해하지 못해도 코드를 짤 수는 있지만, 변수는 사용하기 전에 선언하고 되도록 `let`, `const`를 쓰는 습관을 들이면 호이스팅 때문에 생기는 버그를 애초에 피할 수 있습니다.
