# 화살표 함수와 일반 함수, this가 다르게 동작하는 이유

자바스크립트를 배우다 보면 화살표 함수(`=>`)와 일반 함수(`function`)가 거의 같은 일을 하는 것처럼 보이지만, 결정적으로 다른 부분이 하나 있습니다. 바로 `this`가 가리키는 대상입니다. 이 차이를 모르고 넘어가면 나중에 콜백 함수 안에서 `this`가 이상한 값을 가리키는 버그를 만나기 쉽습니다.

## 일반 함수의 this: 호출 방식이 결정한다

일반 함수의 `this`는 함수를 "누가 호출했는가"에 따라 정해집니다.

```js
const user = {
  name: "지민",
  greet: function () {
    console.log(this.name);
  },
};
user.greet(); // "지민"

const greet = user.greet;
greet(); // undefined (또는 에러)
```

같은 함수라도 `user.greet()`처럼 객체를 통해 호출하면 `this`는 `user`가 되지만, 변수에 담아 단독으로 호출하면 `this`를 잃어버립니다. 그래서 콜백으로 함수를 넘길 때 종종 `this`가 예상과 다르게 동작합니다.

## 화살표 함수의 this: 선언된 위치가 결정한다

화살표 함수는 자신만의 `this`를 만들지 않습니다. 대신 함수가 "정의된 위치"의 바깥 `this`를 그대로 이어받습니다.

```js
const user = {
  name: "지민",
  greet: function () {
    setTimeout(() => {
      console.log(this.name);
    }, 100);
  },
};
user.greet(); // "지민"
```

`setTimeout`에 넘긴 콜백이 화살표 함수이기 때문에, 바깥의 `greet` 함수가 가진 `this`(즉 `user`)를 그대로 사용합니다. 만약 이 콜백을 `function () {}`으로 썼다면 `this`는 `user`가 아니라 전역 객체나 `undefined`가 되어 원하는 값을 얻지 못했을 겁니다.

## 언제 무엇을 써야 할까

객체의 메서드처럼 `this`가 호출 시점에 따라 달라져야 하는 경우에는 일반 함수를, 콜백처럼 바깥의 `this`를 그대로 유지하고 싶은 경우에는 화살표 함수를 쓰는 것이 좋습니다. 이 기준만 기억해도 `this` 관련 버그를 대부분 피할 수 있습니다.
